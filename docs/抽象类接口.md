IRobot 是抽象基类（接口），它做的事情叫面向接口编程 / 依赖倒置。核心不是把 MockRobot从代码里抹掉，而是让所有驱动机器人的代码只依赖 IRobot，不依赖 MockRobot。

robot::MockRobot robot;
  robot.connect();
  while (running) {
      auto s = robot.read();
      robot.submit_target(next_target);
      robot.step();
}

换成接口后：

  std::unique_ptr<robot::IRobot> robot = robot::make_robot();  // 不关心是谁
  robot->connect();
  while (running) {
      auto s = robot->read();
      robot->submit_target(next_target);
      robot->step();
  }

***IRobot最大的作用是实现REALROBOT了之后还是可以用相同的调用方案***

再写robot factory的原因是IROBOT是纯虚函数，不饿能实例化，还是需要去生成一个实例

std::unique_ptr<IRobot> make_robot() {
      return std::make_unique<MockRobot>();   // 全工程唯一一处点名 MockRobot
  }

  将来接真机时，只改这一行：

  return std::make_unique<RealRobot>();   // 全程序瞬间切换，其余零改动

***unique_ptr四个核心特性***
(a) RAII：作用域结束自动释放
(b) 独占所有权：编译期禁止拷贝
(c) 零运行时开销
(d) 支持自定义删除器
调用方不用自己去删除

除了上述的优点，它还实现了:多态
静态类型 IRobot*，动态类型 MockRobot*，调 read() 走 vtable 派发到 MockRobot::read()
静态类型 = 你"看得到"的类型。编译器眼里 r 就是 IRobot*
动态类型 = 对象"真实身份"。r 指向的那块内存里，实际躺着一个 MockRobot
静态类型决定了"能调用什么" 动态类型决定了"实际执行谁"

如果有realrobot，那么Irobot怎么知道派发给哪个实例：
用的是vtable（虚函数表）+ vptr（虚表指针）
vtable 机制——"运行时查表找函数"
